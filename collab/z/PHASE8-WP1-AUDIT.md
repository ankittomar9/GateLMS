## 3. Advisories (non-blocking, fold into WP2 where the curation surface is built out)

- **A-1 — PATCH full-replace overlap edge is untested via the API.** The IT's admin happy-path PATCH ran against a throwaway question with NO pre-existing tags, so the `deleteAll(existing) → save(new QuestionConceptTag(same @EmbeddedId))` path where old∩new ≠ ∅ never executed. `QuestionConceptTag` has an assigned composite ID and no `@Version`, so `save()` always `merge()`s; Hibernate's merge-on-removed entity resurrects it (delete cancelled, state copied) and the pattern is expected to work — but it is spec-undefined behavior relied upon by a curation write path. **Fold into WP2:** one IT case on a real mapped question — `PATCH tags=[A]` → `PATCH tags=[A,B]` → `PATCH tags=[B]` — assert no PK violation and final tags == `[B]`.
- **A-2 — incremental `removeTags` of a non-existent link will 500.** `deleteById(QuestionConceptTagId(...))` on a missing row throws `EmptyResultDataAccessException` → 500 instead of a 4xx. Same WP2 fold-in: catch and 404/400 (or treat as idempotent no-op — pick one and test it).
- **A-3 — N+1 tag lookups on question LIST endpoints.** `QuestionService.toDto`'s fallback fetches `findSlugsByQuestionId` per row, so every paginated list page now issues one extra query per question (50/page today, 3,191-question bank at scale). Detail reads are single-fetch and fine. Not a correctness issue at pilot scale; batch-fetch (`findByIdQuestionIdIn`) or restrict tag population to detail reads when the bank grows / during WP3.
- **A-4 — report LOC figures understate physical line counts** (230 vs 271, 170 vs 180 — code-only vs physical counting). Both readings are far under the ≤600 guardrail; no action, recorded for receipt precision.
- **A-5 — executor housekeeping.** Gemini dual-published the WP1 report to `collab/omnirush/` (retired agent's dir) as well as `collab/gemini/`. Harmless continuity (and it satisfies the spec §8.2 letter, which still names `collab/omnirush/` from pre-retirement drafting); recommend single-sourcing under `collab/gemini/` from WP2 on.
- **A-6 (carried from WP0 audit, confirmed firing):** the template-saturation warning direction inversion (my spec defect, WP0-A-1) still logs noise on every seed run — `[TEMPLATE-SATURATION-WARN] ... (1:1) < 3:1` now fires for ~30 healthy topics including the remediated pilot. Log-only; fix the comparison to `> 3:1` in WP2/WP3 as already dispositioned.
